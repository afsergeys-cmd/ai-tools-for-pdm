# План разработки: «Кто выгуливает Бориса»

## 1. Текущий статус

- Приоритет: собрать минимальное локальное приложение для записи на прогулку с Борисом.
- Текущее состояние: локальная версия приложения и документы подготовлены; базовая проверка API и сохранения после перезагрузки пройдена. Найденная проверка однословного имени исправлена.
- Основная цель цикла: последовательно реализовать и проверить главный сценарий MVP.
- Обязательные ограничения: SQLite для постоянного состояния, атомарная серверная запись, синтетические данные, отсутствие функций вне `spec.md`.
- Основной контекст проекта: `README.md`, `spec.md` и `AGENTS.md`.
- Текущий активный шаг: 2.

## 1.1. Целевой сценарий

1. Сотрудник открывает локальную страницу и видит текущую дату, пять слотов и карточку последнего кормления.
2. Сотрудник выбирает свободный слот, вводит синтетическое ФИО и подтверждает запись.
3. Слот становится занятым и показывает ФИО.
4. Повторная попытка занять тот же слот получает понятный отказ без перезаписи.
5. После обновления страницы или открытия второго браузера запись сохраняется.
6. Сотрудник отмечает кормление, после чего карточка показывает последнее время и ФИО.

## 2. Требования к результату

- `spec.md` остаётся источником продуктовых требований и границ.
- `README.md` описывает фактический способ локального запуска и текущие возможности.
- `AGENTS.md` задаёт обязательный цикл `Spec → Plan → Code → Check`.
- В `PLAN.md` для каждого шага есть действие, результат и проверка.
- Главный сценарий не расширяется авторизацией, отменой записи, календарём или интеграциями.

## 3. Что делаем по шагам

- [x] 1. Первая рабочая версия локального приложения
  - Действие: создать минимальный Node.js-сервер, страницу с текущей датой и пятью слотами, SQLite-схему и серверные операции чтения и записи.
  - Результат: сотрудник может занять свободный слот, а состояние хранится в SQLite.
  - Проверка: запустить приложение локально, увидеть пять слотов и записать синтетического сотрудника.
  - Результат: `node:sqlite` в Node.js, стартовая страница, пять слотов, запись и кормление реализованы. Проверено: пять слотов получены; первая запись `201`, повторная запись `409`, отметка кормления `201`.
  - Дополнительная проверка: однословное значение `тест` отклонено с `400`; «Анна Проверкина» принята с `201`; повторная запись получила `409`; после перезагрузки браузера слот и ФИО остались видны.

- [ ] 2. Отдельная визуальная итерация после проверки в браузере
  - Действие: улучшить читаемость страницы, различие свободных и занятых слотов, карточку кормления и адаптацию для узкого экрана.
  - Результат: главный сценарий заметен и понятен на широком и узком экране.
  - Проверка: вручную открыть страницу в браузере на широком и узком размере и пройти сценарий записи.

- [ ] 3. Отдельная интерактивная итерация — кормление и конфликт записи
  - Действие: добавить отметку кормления, обновление карточки и понятный серверный конфликт при повторной записи.
  - Результат: карточка кормления обновляется, исходная запись не перезаписывается.
  - Проверка: повторно отправить запись в занятый слот, затем отметить кормление и проверить оба результата.

- [ ] 4. Финальная сверка с документами и ручной сценарий
  - Действие: сопоставить реализацию с `README.md`, `spec.md` и `AGENTS.md`, обновить README по фактическому запуску и выполнить полный smoke-check.
  - Результат: все семь DoD подтверждены наблюдаемыми проверками или явно отмечены как невыполненные.
  - Проверка: дата и пять слотов, успешная запись, отказ при повторе, сохранение после обновления/во втором браузере, кормление, широкий и узкий экран.

## 4. Прямые зависимости и проверки

- `spec.md` — продуктовые требования, SQLite-схема, DoD и границы.
- `README.md` — назначение, локальный запуск и фактические возможности.
- `AGENTS.md` — правила работы агента и обязательные ограничения.
- `PLAN.md` — активный шаг и результаты проверок.

## 5. Критерии готовности проекта

- все четыре документа согласованы между собой;
- приложение запускается локально описанным способом;
- главный сценарий проходит от выбора слота до сохранения записи;
- повторная запись не перезаписывает исходное ФИО;
- состояние хранится в SQLite и сохраняется после обновления;
- карточка кормления обновляется;
- проверены широкий и узкий экран;
- функции за пределами `spec.md` не добавлены.
