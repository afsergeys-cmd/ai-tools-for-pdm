# След итерации с ИИ: проверка ФИО при записи

## 1. Задача агенту

Проверить серверную запись на прогулку и кормление: ФИО должно быть непустым после удаления лишних пробелов; повторная запись в занятый слот не должна менять первоначальное имя.

## 2. Что сделал агент

В первой версии сервер принимал любое непустое значение, поэтому строка «тест» могла занять слот. После обнаружения этого поведения серверная проверка была уточнена: требуется не менее двух частей имени, состоящих из букв; допускаются дефис и апостроф внутри части. Такая же проверка применяется к отметке кормления. Добавлен понятный ответ об ошибке.

## 3. Как проверялся результат

- отправка «тест» на свободный слот: HTTP 400;
- отправка «Анна Проверкина»: HTTP 201;
- повторная отправка в тот же слот с другим именем: HTTP 409;
- чтение состояния подтвердило, что в слоте осталось «Анна Проверкина»;
- перезагрузка страницы показала сохранённую запись.

Проверки выполнялись на локальном сервере и с синтетическими ФИО. Снимок отказа для однословного значения не заменяет отдельное подтверждение конфликта занятого слота.

## 4. Почему правка принята

Проверка нашла воспроизводимый дефект: однословная строка не является полным ФИО в сценарии проекта. После изменения однословный ввод отклоняется сервером, корректный синтетический ввод принимается, занятый слот защищён от перезаписи. Это согласуется с формой интерфейса и не расширяет продуктовый скоуп.

## Проверяемость материалов

Старые снимки заменены семью нумерованными файлами в `Скриншоты/`. Кадр серверного конфликта обрезан, чтобы в новом наборе не осталось реального ФИО, присутствовавшего в исходном изображении.
